megahy-backup RELEASE CANDIDATE · 0.4.0-rc4

Your Android data. Your PC. Your choice.

Choose what to copy.
Keep the originals on your phone.

Back up readable files and permitted contacts, SMS, MMS or call logs over USB or Wi-Fi. Pick only what you need. Nothing is installed or deleted on the phone by a backup run.

Not a full-phone backup or a safe-to-reset guarantee.Android may block providers or files. Media filters use file extensions, and exclusions can omit wanted data. Provider exports are archives, not tested restore backups. Windows 10/11 x64 package.

Choose your backup

For example /sdcard/DCIM/Camera, /sdcard/Download, or /storage/ABCD-1234/DCIM. Include subfolders. This is a phone path, not a Windows path.

Media choices match common filename extensions, not actual image/video content. Unknown or missing extensions can be missed. They do not include contacts or messages unless selected below.

Unselected providers are not queried. Android may deny any selected category; no bypass is attempted.

Uncheck to exclude. Hidden means a path component starts with a dot. These are name filters, not a test that files are disposable. Excluding them can skip wanted photos or other files. Nothing is deleted or cleaned.

Faster repeat backups: unchanged files stay in the earlier dated folder and are listed as skipped-unchanged in the report. Turn off for a fresh full comparison.

Save to your PC

Each new run creates a dated megahy-backup folder; an interrupted run can be continued instead of starting over. Existing backups are not overwritten. Keep enough space for your selection; the app checks free space before copying.

Pause waits for the current ADB operation to finish, which may take time for a large file. Resume continues this running session only. Stop ends this session; you can continue the same backup later from where it stopped.

Profiles and saved settings

Your last destination, selection, theme and language are remembered on this PC. Save named profiles for different backup routines.

One-time setup

1. Add Google's ADB. Extract the official Windows Platform-Tools folder next to START-megahy-backup.cmd, or let the app download it from Google:

2. Connect one phone. Enable ordinary USB debugging, use a data cable, unlock the phone and allow this PC. No root or extra phone app is needed.

3. Keep the console open. Do not run two backup apps against the same phone at once. Let an older backup finish before starting this version.

Wi-Fi connection (advanced, Android 11+)

On the phone: Developer options, Wireless debugging. First time, choose Pair device with pairing code and enter the details below. Afterwards only Connect is needed. USB works without any of this. New in this version; tested only in simulation.

Restore files to the phone

Copies verified files from a previous backup back into a dated folder on the phone, and re-checks each hash. It does not restore app data, contacts or messages into their apps. New in this version; tested only in simulation.

Scheduled automatic backups

Windows runs an unattended backup with your saved settings (incremental included) at the chosen time. The phone must be connected. New in this version; tested only in simulation.

Pause is a checkpoint

"Pausing safely" means an operation is still finishing. "Paused" means the app is waiting between device operations. A partial transfer is never counted as verified.

Keep the phone connected and idle while paused. Unplugging is not made safe by Pause. Resume re-checks the pinned device; if it is unavailable, the run ends incomplete. This is not a snapshot.

Know the boundary

  • Copied files: original bytes, formats and modification dates. Windows may still need a codec to open an unusual format. Some filenames are safely mapped for Windows.
  • Provider archives: contacts as vCards, SMS/calls as JSON and CSV, MMS as metadata and binary parts. Not tested for Android restoration.
  • Not extracted: private app data, app chats, authenticator secrets, logins, eSIMs and device settings. Secure folders, work profiles, cloud-only or unreadable files may be absent.
  • Incremental: unchanged files are proven by size and date or by hash before they are skipped. They stay in the earlier backup folder, which the report names.
What does verification mean?

For each verified storage file, SHA-256 matched on the phone before and after copying and on the PC. The report checks copied bytes, not discovery completeness. Provider archives are not source-versus-PC hash verified.

Read REPORT.txt, report.json, the category report and manifest.jsonl. Unselected categories are explicitly marked "not selected". Failed transfers may remain as .partial files, never as verified files.

Local and read-only during backup. No backup upload, analytics, delete or reset function. Backup files are not encrypted. Protect your PC disk and disable USB debugging when finished.
